# pin-pok — Poker Assistant для Pinco

Chrome-расширение читает стол Lucky Chip Hold'em (Pinco и зеркала) и подсказывает действие.
Карты распознаёт локальный Python-сервер (Pillow + OpenCV), банк и стеки берутся из HTML.
Подсказки показываются в **отдельном окне**, поэтому стол не перекрывается — окно можно
отодвинуть на край экрана или на второй монитор.

Репозиторий: https://github.com/ZigelmanMi/pinko-poker

> ⚠️ **Прочитайте перед использованием.** Это вспомогательный инструмент для тренировки и
> разбора рук. Использование подсказок за реальным столом почти всегда нарушает правила
> казино и может привести к блокировке аккаунта и потере средств. Решение использовать
> расширение принимаете вы, ответственность тоже на вас.

## Как это работает

Игра рисует карты на WebGL-холсте (PixiJS), из HTML их не прочитать. Расширение примерно
раз в 2 секунды снимает вкладку и шлёт PNG на `http://127.0.0.1:8765/read`.

```
браузер (Pinco)                       отдельное окно виджета
   │                                         ↑
   ├─ HTML → банк, стек, ники, игроки        │
   │                                         │
   └─ скриншот вкладки                       │
         ↓                                   │
   python: vision_server.py                  │
         ↓  белые карты → ранг + масть       │
   мои карты / доска ────────────────────────┘
         ↓
   эквити: префлоп-диапазоны по позициям,
           постфлоп — Монте-Карло (5 из 7 с кикерами)
         ↓
   FOLD / CHECK / CALL / RAISE
```

| Что видно в виджете | Откуда |
|---|---|
| Мои карты, доска | Python-зрение (`src: py`) или мост из страницы (`src: cv`) |
| Банк, ставка, стек, игроки | HTML стола |
| Рекомендация | Диапазоны позиций (префлоп) и эквити против диапазона (постфлоп) |
| Бейдж `📋 Эквити против диапазона` | решение посчитано локально, без сети |
| Бейдж `⚙️ Монте-Карло: случайные руки` | сработал резервный расчёт (диапазоны недоступны) |

Если Python-сервер выключен, карты часто будут пустыми — это ожидаемо.

## Как запускать

На Windows это один двойной щелчок по `start.bat` (или `npm start`).

Скрипт сам создаёт `.venv`, ставит зависимости, собирает чистую папку `extension\`
и поднимает сервер зрения. Окно не закрывать: в нём живёт сервер. Если сервер уже
отвечает на `/health`, второе окно не запускается.

Первый раз в Chrome:

1. Скрипт откроет `chrome://extensions` и папку `extension\`
2. Включите **Режим разработчика**
3. **Загрузить распакованное** → выберите `extension`, не корень проекта

Дальше расширение остаётся в Chrome. Перед игрой снова `start.bat`, на карточке
расширения **Обновить**, на странице игры **F5**, затем иконка расширения.

Проверка сервера:

```bash
curl http://127.0.0.1:8765/health
# {"ok":true,"engine":"card_vision"}
```

Linux / macOS — по-прежнему два шага, пока нет такого же лаунчера:

```bash
python3 -m pip install -r requirements.txt
./start-vision.sh
```

Папку для Chrome на любой системе собирает `python tools/pack_extension.py`.
Грузить в браузер нужно получившуюся `extension/`.

Виджет — отдельное окно. Перетащите его в сторону от стола. Если закрыли — снова кликните
иконку или нажмите **Tab** на странице игры.

В виджете видно версию, источник карт, сами карты и рекомендацию.

### 3. За столом

- Стол должен быть полностью виден и не перекрыт DevTools.
- Чем больше окно Pinco, тем точнее распознаются карты.
- Если зрение ошиблось — внизу виджета есть поля «Мои карты» / «Доска» и кнопка **Посчитать**.

Решение всегда локальное, без ключей и без запросов наружу:

| Улица | Чем решается |
|---|---|
| Префлоп | диапазоны позиций (`preflop_ranges.js`) |
| Постфлоп | эквити против диапазона + pot odds (`postflop_ranges.js`) |
| Резерв | Монте-Карло против случайных рук + pot odds |

## Экономия ресурсов

Скриншот всей вкладки — самая дорогая операция в расширении, поэтому она делается
только тогда, когда это действительно нужно:

1. **Сначала мост.** `page_bridge.js` умеет читать карты прямо из canvas/React/Pixi.
   Если карты получены оттуда, скриншот не запрашивается вообще (в виджете это видно
   как `без съёмки: N`).
2. **Затем dhash.** Если кадр всё же снят, его perceptual hash сравнивается с предыдущим.
   Совпал — на сервер ничего не отправляется, используется прошлый результат
   (`из кэша: N`).
3. **Только потом сервер.** Если картинка изменилась, PNG уходит на `127.0.0.1:8765`.

Статистика видна прямо в виджете: `📷 скриншотов: N, из кэша: N, без съёмки: N`.

## Если карты пустые

1. Жив ли сервер: `curl http://127.0.0.1:8765/health`
2. В виджете `src: py`? Если нет — Python не ответил, смотрите его консоль.
3. Обновите расширение и нажмите F5 на странице игры.
4. Уберите DevTools с области стола.
5. Посмотрите `chrome://extensions` → карточка расширения → **Ошибки**: если контент-скрипт
   упал, там будет текст исключения.

## Если Chrome не загружает расширение

Частая причина: **Chrome не принимает файлы и папки, имена которых начинаются с `_`.**
Обычно это `__pycache__`, который Python создаёт рядом с исходниками.

Проверить и починить:

```bash
npm run preflight                          # покажет, что мешает загрузке
Remove-Item -Recurse -Force __pycache__    # или: rm -rf __pycache__
```

`start-vision.ps1` и `start-vision.sh` запрещают создание байт-кода, поэтому при
запуске сервера через них папка остаётся чистой.

## Разработка и проверки

В проекте есть автотесты, которые запускаются без браузера:

```bash
npm run check          # синтаксис всех JS-файлов
npm run test           # все наборы тестов
npm run verify         # и то и другое
npm run test:e2e       # отдельно: сквозная проверка на синтетическом столе
npm run test:server    # отдельно: HTTP-слой сервера зрения (нужен Python)
```

Что покрыто:

- `test_hand_eval.js` — все 9 категорий комбинаций, тайбрейкеры и кикеры, «колесо»,
  5 из 7, а также эквити против эталонных значений, посчитанных полным перебором
  (AA vs KK = 82.64%, AKs vs QQ = 46.21% и т. д.);
- `test_range_equity.js` — эквити против **диапазона**: сверка с полным перебором,
  взвешивание комбинаций, блокирование карт, несколько соперников;
- `test_preflop_ranges.js` — диапазоны открытий/3-бетов/защиты BB и инварианты решений;
- `test_postflop_ranges.js` — диапазоны по типам банков, сужение по борду и агрессии,
  решения по pot odds;
- `test_action_logic.js` — локальный выбор действия: позиция, ситуация, постфлоп-банк,
  резерв Монте-Карло;
- `test_frame_diff.js` — сравнение кадров dhash: устойчивость к шуму, реакция на сдвиг;
- `test_parser_node.js` — разбор карт из DOM и SVG;
- `test_dom_e2e.js` — сквозная проверка: синтетический стол → парсер читает карты, банк,
  ставки, игроков и стеки → считается эквити против случайных рук и против диапазона.

Отдельно, опционально (нужен `playwright`):

```bash
pip install playwright && python -m playwright install chromium
python test_parser_svg.py
```

Эта проверка гоняет настоящий Chrome и парсер SVG, поэтому в `requirements.txt` её
зависимости не добавлены.

## Приватность и безопасность

- Скриншоты вкладки отправляются **только** на `127.0.0.1:8765`, то есть никуда не уходят
  из вашей машины. Карты в облако не отправляются.
- Расширение работает только на домене игры: `manifest.json` ограничен `*.e5t.online`,
  а `content.js` дополнительно проверяет хост. Раньше стоял доступ ко всем сайтам, из-за чего
  расширение могло снимать скриншоты посторонних страниц.
- Локальный сервер принимает запросы только с допустимым `Origin`, ограничивает размер тела
  запроса (8 МБ) и частоту (не чаще 0.4 с).
- `page_bridge.js` подменяет `window.WebSocket` и читает WebGL-кадр. Это необходимо для
  чтения карт, но такое вмешательство в страницу потенциально заметно для античита.
- Наружу не уходит ничего: ни карты, ни текст руки. Сервер зрения слушает только `127.0.0.1`.

## Ограничения, о которых стоит знать

- Позиция героя по-прежнему оценка: фишки дилера в HTML нет. Неоткрытый банк
  считается с самой ранней позиции этого стола, а не с кнопки. Добор 1.2–2 ББ —
  большой блайнд против открытия, 2–6 ББ — колл открытия с CO, от 6 ББ — против героя 3-бет.
- Диапазоны префлопа и постфлопа — это усреднённые чарты для 6-max, а не решение конкретного
  солвера. Они не учитывают статистику соперников.
- Тип постфлоп-банка выводится из размера банка и ставки, полной истории действий в HTML нет.
  Банк от ~12 ББ считается 3-бет-банком. В меньшем банке ставка в героя — диапазон
  префлоп-агрессора, чек до героя — диапазон коллера.
- Сужение постфлоп-диапазона по борду и агрессии — эвристические множители, а не GTO-частоты.
- Постфлоп-эквити считается против диапазона в предположении «мы против одного соперника»;
  в мультивее диапазон берётся одинаковым для всех.
- Монте-Карло даёт оценку с погрешностью около ±1 п.п. при используемом числе итераций.
- Распознавание карт зависит от размера окна: стол должен быть виден целиком.
